# 项目使用与故障排查

## 本地启动需要哪些服务

Web 使用两个 Python 进程：FastAPI 默认监听本机 8000 端口，Streamlit 默认监听本机 8501 端口。Memory 模式不依赖 Redis；选择 Redis 会话或限流后，还需要可连接的 Redis。DeepSeek 和 SiliconFlow 密钥只在后端读取，不填到网页或提交到 Git。Python 版本为 3.12，依赖安装与启动命令以 README 为准。

## 页面无法连接后端怎么办

先确认后端进程仍在运行，访问 `/health` 检查进程是否响应，再访问 `/ready` 检查启用的会话和限流依赖。检查前端的 `RAG_API_URL` 是否与后端地址一致，并确认端口未被其他程序占用。`/ready` 返回成功不代表模型网络和整条知识库链路都已经验证，不要仅凭前端页面打开就认定后端可用。

## 为什么健康检查成功却无法回答

`/health` 只验证 API 存活，`/ready` 主要验证配置的状态依赖；实际问答还需要解析知识库、调用 Embedding、检索和访问 DeepSeek。因此密钥无效、外部服务不可用或索引异常，都可能造成问答失败。应按接口错误提示和脱敏日志排查对应环节，不要在截图或日志中暴露真实密钥。

## 上传文件有哪些限制

第一版支持 Markdown 和 UTF-8 TXT，默认单文件 5 MB，可通过环境变量调整。程序检查文件名、扩展名、大小、空内容、UTF-8 编码及明显的二进制内容，并使用生成的存储名保存原文。扩展名正确不等于内容一定有效。PDF、Word 和扫描件当前没有专门解析器，应先转换为支持的文本格式再检查内容。

## 上传同名文件会发生什么

清理后的文件名用于识别同一份上传文档；同名上传按更新处理，生成新的版本文件和片段 ID。成功发布后清理旧版本的向量与文件，失败时尝试补偿回滚。同名更新不是新增第二份独立文档；若要同时保留两个版本供查询，应使用不同文件名，并在正文写明版本和适用范围。应用层回滚不等于跨文件和向量库的严格事务。

## 服务重启后哪些数据会保留

本地 Chroma、上传原文和清单保存在持久化目录，正常重启后仍可加载。Memory 会话和限流计数会清空。Redis 会话可跨 API 进程共享，但 Redis 自身重启后的保留情况取决于持久化配置。CLI 的聊天历史只属于当前 CLI 进程，不与网页共享。不要把知识库持久化与聊天历史持久化混为一谈。

## 为什么同一会话再次提问会返回 409

同一会话已有问题正在处理时，第二个请求会被拒绝，避免读取旧历史后并发生成或覆盖结果。应等待当前请求完成，再继续追问；清空会话也使用相同的会话锁。不同 Session 的对话历史隔离，但当前知识库文档是共享的。Session UUID 不是账号权限，当前没有用户登录或租户知识库隔离。

## 429 请求过于频繁是什么意思

429 表示触发请求额度，客户端应参考 `Retry-After` 等待后再试。问答同时限制 IP 与 Session 组合额度和 IP 总额度，上传按 IP 限制；Redis 模式会跨后端实例共享计数。当前 Streamlit 转发请求，后端通常看到的是 Streamlit 服务 IP，因此多个浏览器用户可能共享 IP 总额度。公开部署需要可信客户端身份设计，不能直接信任任意转发头。

## Redis 故障会影响哪些功能

如果会话或限流选择 Redis，相应操作遇到 Redis 故障会返回 503，不会静默退回各进程的内存历史。进程存活检查仍可返回 200，本地文档列表和原文预览不因 Redis 单独故障而必然失效。Redis 恢复后连接池可以重新连接；若启用 Redis 时启动检查就失败，API 会拒绝启动，需要先修复连接配置。

## 已经显示答案但提示历史未确认保存怎么办

模型可能已成功生成答案，而 Redis 提交或确认响应失败。程序会使用同一个 request ID 有限重试，避免响应丢失后重复追加；仍无法确认时保留答案，并提示本轮历史状态为 unconfirmed。此时不能确定“肯定没保存”或“肯定已保存”。可以阅读现有答案，后续追问时补充必要上下文，不应自动重新生成同一回答。

## 为什么生成期间不能切换模式

模式开关属于 Streamlit 控件，变化会触发脚本重跑，可能打断正在读取的流。当前界面在请求前锁定模式，并在生成期间禁用切换和其他会触发重跑的操作，结束或失败后恢复。侧栏折叠及页面阅读不改变本次后端模式。相关追问使用同一 Session，但按照点击时选定的模式提交下一条问题。

## 流式回答中断后能否自动续写

当前接口以 SSE 传递 token、工具事件、完成事件或错误。前端只有收到 done 才确认本轮完成；连接提前结束会提示失败。当前没有基于事件 ID 的断点续传，也不保证浏览器刷新后能接回原请求。不要把已显示的半截文本视为完整答案；重试前应等待旧请求释放会话执行权。

## 相关追问是大模型实时生成的吗

当前不是。系统在本地根据本轮问题、回答、检索片段和当前可用文档选择维护过的主题，并可从检索片段标题提取问题。最多显示三个，按规范化文本排除本会话已问过的问题。它不额外消耗模型调用，也不代表系统已经验证每个推荐问题都能被完整回答。没有匹配资料或本轮失败时，可以不显示推荐。

## 如何备份知识库和更换 Embedding 模型

备份应同时覆盖内置文档、上传原文及清单、Chroma 目录和非密钥的模型/索引配置。避免在写入过程中直接复制不一致的文件集合。更换 Embedding 模型可能改变维度和向量空间，应在独立的新索引中重新向量化并验证，再切换配置；不要直接混用新旧模型生成的向量。当前没有自动索引迁移或零停机切换功能。

## 当前项目可以直接多机器部署吗

会话与限流可以通过 Redis 跨进程共享，但上传原文、JSON 清单、本地 Chroma 和运行时文档视图仍属于本地知识库单点。不能仅因为接入 Redis 就让多台机器分别写入各自的数据目录。完整扩展还需要统一文档存储、可共享的向量服务、更新发布机制和访问控制；这些不是当前实现已经完成的能力。
