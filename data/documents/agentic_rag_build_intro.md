# Agentic RAG 搭建流程

## Agentic RAG 搭建流程总览

Agentic RAG 是将 Agent 的工具选择能力与 RAG 知识检索结合起来的系统。大语言模型根据用户问题决定是否调用工具，程序负责执行工具，再把结果交回模型生成回答。

一个基础 Agentic RAG 系统通常包括以下步骤：

1. 明确 Agent 要处理的问题范围和工具权限。
2. 准备可调用的工具，并定义每个工具的用途和参数。
3. 创建 Tool Schema，让模型了解可用工具。
4. 使用 Tool Registry 将工具名称映射到程序函数。
5. 编写 Tool Executor，检查并分发模型提供的工具参数。
6. 接收用户问题，让模型决定直接回答或调用工具。
7. 执行工具并将结果放回对话上下文。
8. 让模型依据工具结果生成最终回答。
9. 对工具选择、参数、执行结果和最终回答进行测试与评估。

简要链路是：用户问题 → 模型选择工具 → 程序执行工具 → 工具结果回传 → 模型生成回答。多轮工具循环、重试、权限控制和复杂上下文管理属于可扩展能力，不是所有基础实现都会包含。

## Agentic RAG 是什么

Agentic RAG 将 RAG 的知识检索能力纳入 Agent 的工具体系。传统 RAG 通常按预设流程检索资料并生成答案；Agentic RAG 则由模型根据问题判断是否需要检索，或选择其他工具完成任务。

例如，用户询问知识库中的具体概念时，Agent 可以调用知识搜索工具；用户询问知识库包含哪些资料时，可以调用来源列表工具。工具返回结果后，模型再依据这些结果组织回答。

Agentic RAG 的能力取决于实际提供的工具和程序逻辑。模型只能选择系统开放的能力，工具调用本身由应用程序执行。

## 第一步：明确任务范围和工具权限

设计 Agent 前，应明确它需要解决哪些问题，以及它可以执行哪些操作。工具应围绕具体任务设计，避免向模型开放不必要的能力。

知识库问答 Agent 常见的只读工具包括：

- 搜索知识库内容。
- 列出知识库资料来源。
- 查询特定类别或时间范围内的资料。

如果工具会修改数据、发送消息、访问敏感资源或产生费用，应在程序中设置权限检查和必要的用户确认。模型返回的工具调用不能直接视为已授权操作。

本项目的 Agent 面向本地知识库问答，只开放知识搜索和来源列表两个工具。

## 第二步：设计工具

每个工具应有明确的职责、输入参数和返回格式。工具粒度要适中：太宽泛时模型难以正确使用，太零散则会增加选择难度和维护成本。

例如，知识搜索工具可以接收一个问题，返回相关片段的内容、来源和顺序；来源列表工具可以返回当前知识库中去重后的来源名称。

工具实现应尽量返回完成任务所需的信息，并处理空结果和运行异常。这样模型可以理解工具是否找到资料，也能据此说明知识库内容不足。

本项目在 `src/tools.py` 中实现：

- `knowledge_search`：调用现有混合检索，返回片段内容和来源。
- `list_knowledge_sources`：返回当前加载文档中的来源列表。

## 第三步：编写 Tool Schema

Tool Schema 用于向模型描述可用工具，包括工具名称、用途说明、参数结构和必填字段。模型根据 Schema 判断何时调用工具，并生成相应参数。

Schema 应清楚说明：

- 工具适合处理哪些问题。
- 参数代表什么，应该使用什么格式。
- 哪些参数必须提供。
- 工具能返回什么类型的信息。

如果工具描述模糊、名称相似或参数定义不清，模型可能选错工具或生成无效参数。Schema 只描述工具接口，不会自动执行函数。

本项目在 `src/tool_schemas.py` 中定义两个工具的名称、描述和参数：`knowledge_search` 需要 `question` 参数；`list_knowledge_sources` 不需要参数。

## 第四步：建立 Tool Registry

Tool Registry 是工具名称到程序函数的映射。模型返回工具名称后，程序通过注册表找到对应函数。

注册表应只包含允许调用的工具。遇到未注册名称时，应拒绝执行，而不是执行模型提供的任意函数或代码。

本项目的 `src/tool_registry.py` 将 `knowledge_search` 和 `list_knowledge_sources` 映射到对应函数，并在遇到未知工具时抛出错误。

## 第五步：编写 Tool Executor

Tool Executor 负责把模型给出的工具名称和参数交给正确函数执行，并返回工具结果。它是模型输出与程序函数之间的边界。

执行时应检查：

- 工具是否已注册。
- 必填参数是否存在。
- 参数类型和格式是否符合预期。
- 工具执行是否成功。
- 返回结果是否能安全地传回模型。

模型输出应被视为外部输入。即使工具 Schema 已定义参数，程序端仍应验证关键字段，不能只依赖模型遵守格式。当前项目的 Executor 会按 Schema 检查参数对象、必填参数、未定义参数和已声明的基本类型；复杂嵌套结构、字符串长度及业务边界仍需按工具需要补充校验。

本项目在 `src/agent.py` 的 `execute_tool` 中根据工具名称调用不同函数，并传入文档列表和向量数据库等运行时对象。

## 第六步：让模型决定是否调用工具

程序将系统说明、用户问题和 Tool Schema 一起发送给大语言模型。模型可能直接返回普通回答，也可能提出一个或多个工具调用请求。

模型是否调用工具会受到问题表达、系统提示词和工具描述影响。系统提示词应说明工具用途，并要求模型在知识库相关问题上根据需要使用工具。

本项目通过 `ChatOpenAI` 调用 DeepSeek，并将 `TOOL_SCHEMAS` 传给模型。若模型没有返回工具调用，`run_agent` 会直接返回模型文本。

## 第七步：执行工具并回传结果

模型提出工具调用后，程序解析工具名称和参数，通过 Tool Registry 与 Executor 执行相应函数。执行结果再以工具消息的形式加入对话上下文。

工具结果应尽量简洁、结构清楚，并包含来源等回答所需的信息。若结果为空，模型应能据此说明没有找到相关资料，而不是假装检索到了依据。

本项目将工具结果编码为 JSON，并包含工具调用 ID，随后添加到消息列表。`knowledge_search` 的返回结果包含片段序号、内容和来源；来源列表工具返回来源名称列表。

## 第八步：根据工具结果生成回答

程序把包含工具结果的消息再次发送给模型，由模型将结果整理为面向用户的最终回答。

提示词应要求模型依据工具结果回答、准确表达资料不足的情况，并避免补充工具结果中没有的事实。若答案需要引用来源，工具返回结构应包含足够的来源信息。

本项目在工具调用结束后再次调用 DeepSeek，并返回模型生成的最终回答。当前实现会在第一次模型响应后执行返回的工具调用，然后进行一次最终模型调用；它没有实现不限定轮数的持续工具调用循环。

## 第九步：处理错误、空结果与停止条件

Agent 应区分不同类型的失败，例如模型服务不可用、Embedding 服务失败、工具名称未知、参数无效和工具运行异常。程序应给用户清晰提示，并避免单次问答失败导致整个交互程序退出。

知识库为空或搜索结果为空时，应返回明确状态，让模型或应用程序能诚实说明没有找到资料。工具调用还应设置数量或轮数限制，避免反复调用造成请求失控。

本项目的 `agent_qa.py` 会在知识库为空时提示用户添加 Markdown 文档，并针对 Embedding 和 DeepSeek 服务异常提示重试。单次问答出现其他异常时也会显示错误并继续交互。当前工具处理轮数是固定的一轮工具执行后再生成最终回答。

## 第十步：测试与评估 Agent

Agent 评估除了检查最终回答，还要检查模型是否选择了正确工具、参数是否正确、执行器是否调用了正确函数、工具结果是否回传，以及最终回答是否忠实于结果。

可以使用模拟模型构造固定响应，测试以下情况：

- 模型直接回答，不调用工具。
- 模型正确选择已注册工具。
- 模型返回未知工具。
- 必填参数缺失或格式错误。
- 工具返回空结果或运行失败。
- 模型请求多个工具。
- 工具结果被正确传回并用于最终回答。

还可以建立一组代表性用户问题，记录预期工具和预期依据，比较修改 Schema、提示词或工具实现前后的表现。

本项目包含针对 Agent 逻辑、工具注册和工具 Schema 的离线测试，并提供调用真实 DeepSeek 服务的工具选择集成测试。

## Agentic RAG 的可选扩展

基础实现可以根据应用需求加入以下能力：

- **多轮工具循环**：允许模型在读取工具结果后继续选择工具，并设置最大轮数。
- **更严格的参数验证**：使用数据模型校验复杂结构、字符串长度和业务边界；当前只做 Schema 基础检查。
- **重试与超时**：对临时服务错误进行有限重试，并设置请求超时。
- **工具调用日志**：记录工具名称、执行状态和错误信息，方便排查。
- **权限与确认**：对敏感或有副作用的操作进行访问控制或要求确认。
- **并行工具调用**：当多个互不依赖的工具都需要执行时并行处理。
- **结果压缩与上下文管理**：控制工具结果长度，避免超过模型上下文限制。

这些能力不是 Agentic RAG 的必选项，应根据实际任务、风险和维护成本决定是否实现。

## 项目当前 Agentic RAG 实现

| 环节 | 当前项目实现 |
|---|---|
| 用户入口 | `agent_qa.py` 命令行交互 |
| 知识搜索 | `knowledge_search`，调用项目的混合检索 |
| 来源查询 | `list_knowledge_sources`，返回已加载文档来源 |
| 工具定义 | `src/tool_schemas.py` 中的 Tool Schema |
| 工具注册 | `src/tool_registry.py` 中的名称与函数映射 |
| 工具执行 | `src/agent.py` 中的 `execute_tool`，按 Schema 检查必填项、未知参数和基本类型 |
| 工具选择 | DeepSeek 根据问题和 Tool Schema 决定是否调用工具 |
| 结果回传 | 以工具消息和 JSON 内容加入对话 |
| 最终回答 | DeepSeek 基于工具结果生成 |
| 错误处理 | 入口捕获服务错误和单次问答异常，并继续交互 |
| 多轮工具循环 | 当前未实现持续多轮调用；一次模型工具选择后执行工具，再生成最终回答 |
